# UI 전면 개편 기록

## 설계 결정

- 요청 입력과 추천 결과를 Flask의 별도 페이지로 분리했습니다.
- 사이드바는 신규 배차와 진행 단계만 남겼습니다. 기능 없는 탐색 항목을 만들지 않았습니다.
- 입력은 운송 구간 → 화물 → 확인 요약 → 조회 순서로 구성했습니다.
- 결과는 운송건 요약 → Route View와 차량 비교 → 하단 선택 차량 → 최종 확인 → 완료 순서입니다.
- 전체 차량 현황과 최근 이력은 메인 화면에서 제거했습니다. 필요한 차량 상태는 후보 카드 상세에 통합했습니다.
- 실제 모델에 종합 점수와 미래 일정 충돌 검사가 없으므로 이를 임의로 계산하거나 안전하다고 표시하지 않습니다.
- 지도는 표시 전용입니다. 온라인 도로 서비스가 모델의 점수·거리·시간을 변경하지 않습니다.

## 최초 UI 개편 당시 모델 보존

`model/dispatch_model.py`, 데이터 변환과 컨테이너·중량 서비스의 계산 로직은 이번 UI 작업에서 변경하지 않았습니다. 기존 추천 API를 페이지에서 직접 호출합니다.

새 API `GET /api/orders/<order_id>`는 서버의 확정 결과 복원용입니다. 서버 상태와 다른 성공 화면을 브라우저 캐시만으로 만들지 않습니다.

## 검증

통합 테스트 7개와 실제 Chrome 업무 흐름 검증을 수행했습니다.

- 입력과 결과의 별도 URL 및 전용 DOM 구조
- 실제 모델의 769대 평가, 예시 운송건의 적합 74대·추천 1순위 차량0308 일치
- 실제 OSM 타일 및 OSRM 도로 경로 로딩
- 자차/용차 필터, 선택 변경, 확인창 취소·확정
- 서버 저장, 확정 후 새로고침 복원, 확정 차량의 다음 추천 제외
- WARN 유지, BLOCK 중단, 입력 수정 복원, 후보 없음
- 실제 공차 이동이 있는 후보의 선택과 경로 표시
- 모바일 입력·결과 화면의 가로 넘침 없음
- 외부 지도 연결 실패 시 안내와 로컬 추천·확정 기능 유지
- 입력 초안 없이 결과 URL에 직접 접근 시 안내
- 브라우저 JavaScript 오류 없음

테스트는 임시 배차 저장소를 사용합니다. 사용자의 실제 확정 데이터는 수정하지 않습니다. 테스트 재실행 명령과 지도 서비스 제한은 README를 참고하세요.

## 지정 컨테이너 입력 개편 (2026-09-10)

- 화물 종류와 적재 규격 자동 판정 카드를 제거했다.
- 요청서의 지정 컨테이너 타입을 8개 클릭 카드 중 필수 선택하고 중량을 입력한다. 화물명 입력과 Size/Type 안내 문구는 제거했다.
- 미리보기·WARN/BLOCK 대화상자·추천 결과·최종 확정·저장 및 복원에서 지정 타입을 유지한다.
- 컨테이너 미입력 시 조회를 막고, 이전 미확정 초안에 타입이 없으면 입력 화면에서 선택하도록 안내한다.
- 타입별 중량 기준만 검사하며 실제 차량별 장비 호환 데이터는 제공되지 않는다. 확정창에서 장비 확인을 안내한다.
- 검증은 `tests/run_tests.py`, `tests/browser_check.py`로 실행한다. 아래 스크린샷은 테스트 실행 시 최신 화면으로 갱신된다.
