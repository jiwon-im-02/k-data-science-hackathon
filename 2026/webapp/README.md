# ROUTE:ONE · 차량 배차 추천 워크스페이스

실제 차량 이력과 OD(거점 간 거리·시간) 데이터를 사용해 운송 가능한 차량을 추천하고, 담당자가 비교·선택한 차량에 배차를 확정하는 Flask 웹 애플리케이션입니다.

**신규 운송건 입력 → 추천 결과 페이지 → 경로 확인 → 차량 비교·선택 → 배차 확정**

입력과 결과를 별도 URL로 분리했습니다. 차량 상태는 추천 카드에 통합하고, 차량 현황·최근 배차 내역·KPI는 메인 업무 흐름에서 제외했습니다. 추천은 기존 수정 모델을 호출하며 화면용 Mock 차량이나 임의 점수로 대체하지 않습니다.

## 빠른 실행

이미 설치했다면 프로젝트 폴더에서 다음 명령만 실행하세요. 가상환경을 활성화하지 않아도 됩니다.

```powershell
cd "./웹페이지"
.\.venv\Scripts\python.exe app.py
```

브라우저에서 **http://127.0.0.1:5000** 에 접속합니다. 서버를 종료하려면 터미널에서 `Ctrl+C`를 누릅니다. 수정 전 서버가 실행 중이라면 종료 후 다시 실행하고 브라우저에서 `Ctrl+F5`로 새로고침하세요.

다른 PC에서는 아래 설치 절차를 따릅니다. 위 절대경로는 현재 PC용 실행 예시이며, 소스코드 경로는 `config.py`에서 프로젝트 폴더를 기준으로 계산합니다.

## 설치 방법

Python 3.10 이상이 필요합니다. PowerShell에서 제출 폴더 `웹페이지`를 연 뒤 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m model.data_builder_revised
.\.venv\Scripts\python.exe app.py
```

데이터셋이 이미 제공된 경우 데이터 변환 명령은 생략할 수 있습니다. 원본 Excel이 바뀌면 다시 변환하세요. pip 새 버전 안내는 오류가 아니므로 업데이트는 필수가 아닙니다.

macOS/Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m model.data_builder_revised
.venv/bin/python app.py
```

Node.js, 프론트엔드 빌드, 지도 API 키는 실행에 필요하지 않습니다.

## 모델 코드와 웹페이지 연결 구조

1. `data_builder_revised.py`가 실제 FIXED 이력, 자차/용차 구분, OD 거리·시간, 거점 좌표를 읽습니다.
2. 입력 페이지는 `POST /api/container`로 지정 컨테이너 타입을 검증하고 해당 타입의 중량 Gate를 호출합니다.
3. OK는 바로 결과 화면으로 이동합니다. WARN은 중앙 확인창에서 주의사항을 확인한 뒤 진행하며, BLOCK은 중앙 차단 안내 후 입력 화면에 남습니다. 진행 가능한 입력값만 브라우저 탭에 보관합니다.
4. 결과 페이지는 `POST /api/recommend`를 호출합니다. 서버가 입력한 컨테이너 타입과 해당 중량 Gate를 재검증하고 기존 `DispatchEngine.recommend()`를 실행합니다.
5. 프론트엔드는 반환된 순위를 그대로 표시합니다. 지도 도로 서비스의 거리·시간으로 모델 결과를 덮어쓰지 않습니다.
6. `POST /api/dispatch`는 최신 저장 상태로 추천을 다시 계산해 선택 차량의 유효성을 확인한 다음 배차를 저장합니다.
7. `GET /api/orders/<order_id>`는 확정 결과를 복원합니다. 새로고침 또는 확정 응답 연결 끊김 시 중복 확정을 방지하는 화면 처리에 사용합니다.
8. `GET /api/evaluation`은 기존 수정 모델의 평가지표를 제공합니다.

수정 모델의 후보 판정식을 유지하고, 동률 후보의 운영상 우선순위는 화면과 모델에서 다음과 같이 명확히 적용했습니다.

```text
작업 간격 = 주문 시각 - 차량 가용 시각
후보 조건 = 0 < 작업 간격 <= 24시간

예상 도착 = 차량 가용 시각 + 공차 이동시간
도착 여유 = 주문 시각 - 예상 도착
후보 조건 = 도착 여유 >= 25분

추천 순서:
공차거리 오름차순
→ 도착 여유 25분에 가까운 순 → 가용 후 경과시간 짧은 순 → 차량 ID
```

현재 수정 모델은 가중 Objective Cost, 100점 만점 종합 점수, 이후 FIXED 일정 복귀·충돌 검사를 산출하지 않습니다. UI에도 점수나 '충돌 없음'을 임의로 만들지 않고 추천 순위와 이후 예정 배차 확인 안내를 표시합니다.

25분은 최소 도착 여유 조건이자 같은 공차거리 후보를 비교하는 운영 기준입니다. 따라서 24시간 가까이 오래 대기해 상태 신뢰도가 낮을 수 있는 차량이 1시간 전에 가용해진 차량보다 단순히 여유시간이 크다는 이유로 앞서지 않습니다. 공차 이동시간은 예상 도착 계산과 화면 비교에는 사용하지만, 공차거리와 중복되는 별도 정렬 기준으로 사용하지 않습니다.

## 입력 데이터 설명

- `data/source/모델링_최종후보표.xlsx`: 차량 마스터, 기존 후보, 대표 거점 좌표
- `data/source/순차모델링_OD캐시.xlsx`: 거점 사이 도로거리와 예상 이동시간
- `data/source/순차모델링_FIXED스케줄.xlsx`: 차량의 과거 운송 상태 이력
- 상·하차지는 자동완성에 제공된 거점명으로 선택합니다.
- 상차 일시는 KST 기준, 화물 중량은 kg 단위입니다.
- 운송 요청서에 지정된 컨테이너 타입을 필수 입력합니다: 20DC, 20RF, 20TK, 40DC, 40HC, 40OT, 40RF, 45HC.
- 화면에서는 컨테이너 8개 타입을 선택 카드로 표시하며 화물명은 입력받지 않습니다. 기존 화물 종류·적재 규격 자동 판정 입력은 제거했습니다.
- 타입은 중량이 바뀌어도 유지됩니다. 예: 20DC / 21,750kg은 40DC로 변경되지 않고 BLOCK입니다. 가벼운 화물도 요청서에 지정된 40DC/40RF/45HC를 그대로 입력할 수 있습니다.
- 현재 원본에는 차량별 장착 샤시·허용 컨테이너 목록이 없습니다. 과거 운송 타입을 차량 장비 호환성으로 간주하지 않습니다. 지정 타입의 중량 Gate를 통과한 주문에 기존 시간·거리 추천을 적용하며, 실제 차량 장비 호환성은 담당자가 확인합니다.
- 중량 Gate는 제공된 모델 기준이며 실제 차량별 허용 적재량을 판정하는 기능은 아닙니다.
- 제공 이력이 2026년 1~3월이므로 시연 예시는 **2026-03-18 09:00 / 의왕ICD → 부산신항 / 18,000 kg**입니다.
- **부산북항 → 의왕ICD / 동일 일시**는 상차 거점 밖에서 이동하는 공차 후보를 확인하기 좋습니다.

## 지정 컨테이너 입력 API

`POST /api/container`(미리보기), `POST /api/recommend`(추천) 모두 아래 입력을 사용합니다.

```json
{
  "pickup": "의왕ICD",
  "dropoff": "부산신항",
  "work_time": "2026-03-18T09:00",
  "container_type": "40DC",
  "weight_kg": 18000,
  "cargo_type": "기계 부품"
}
```

- `container_type`은 필수이며 앞뒤 공백과 대소문자만 정규화합니다. 미입력/미지원 타입은 HTTP 400으로 거절하며 자동 추정하지 않습니다.
- `cargo_type`은 선택 화물명입니다. 기존 `refrigerated`, `liquid`, `special_cargo`, `cargo_profile`은 타입을 변경하지 않습니다.
- `POST /api/dispatch`는 `{"vehicle_id": "...", "order": {...}}`를 받습니다. order에는 추천 시 반환된 `order_id`와 동일한 지정 타입·운송 정보를 포함합니다.
- Gate는 지정 타입의 BLOCK 기준 **이상**을 차단합니다. WARN/BLOCK 확인창에는 지정 타입, 입력 중량과 해당 한도가 표시됩니다.
- 저장된 기존 배차는 변경하지 않습니다. 타입이 없는 이전 미확정 브라우저 초안은 입력 화면에서 타입을 선택해야 다시 조회할 수 있습니다. 이미 확정된 주문은 기존 저장 내역으로 복원합니다.

## 화면별 사용 방법

### 1. 신규 운송건 입력 · `/`

운송 구간, 지정 컨테이너 타입과 화물 중량을 입력합니다. 8개 컨테이너 타입 중 하나를 클릭하여 선택합니다. 오른쪽 요약에서 컨테이너·중량 상태를 확인하고 **추천 차량 조회**를 누릅니다. WARN은 중앙 확인창에서 명시적으로 계속 진행할 수 있으며 결과 화면에서도 상단 경고가 유지됩니다. BLOCK은 계속 진행할 수 없고 중앙 안내창에서 입력값 수정만 선택할 수 있습니다.

### 2. 추천 차량 비교 · `/recommendations`

상단 요약을 확인하고 지도와 후보를 비교합니다. 차량 카드는 실제 모델의 상위 10대를 표시하며, 자차/용차 필터는 이 표시 후보에 적용됩니다. 필터를 바꿔도 원래 추천 순위는 유지됩니다.

카드의 **배차 선택**을 누르면 선택 상태, 지도와 하단 확정 영역이 함께 바뀝니다. 선택한 차량을 숨기는 필터로 변경하면 선택을 해제합니다. '가용 상태 및 추천 상세'에서 현재 작업, 가용 시각, 완료 예정 등을 확인할 수 있습니다.

데스크톱에서는 후보 목록을 별도로 스크롤해 지도를 계속 보면서 비교합니다. 작은 화면에서는 지도와 후보가 세로로 배치됩니다.

### 3. 배차 확정

**배차 확정** 버튼으로 확인창을 열고 운송건·차량·주의사항을 검토한 후 최종 확정합니다. 서버는 배차 가능 여부를 재검증하고 완료 화면을 표시합니다. 이후 신규 운송건에는 하차 거점과 완료 예정 시각을 반영한 차량 상태가 사용됩니다.

확정 이력 목록과 전체 차량 현황은 이번 핵심 흐름에서 제외했습니다. 저장 데이터 및 기존 평가 API는 유지합니다.

## 지도 사용과 주의사항

- API 키가 필요하지 않습니다. 배경 지도와 도로 경로에는 인터넷이 필요합니다.
- 배경은 [OpenStreetMap](https://www.openstreetmap.org/copyright), 도로 도형은 [OSRM Route Service](https://project-osrm.org/docs/v5.22.0/api/)를 사용합니다.
- 지도 접근 시 화면 영역의 타일 좌표, 도로 조회 시 상·하차 및 선택 차량의 대표 거점 좌표가 외부 서비스에 전달됩니다. 차량 ID·기사 정보·화물 정보는 전송하지 않습니다.
- 좌표는 이력의 **대표 거점**이며 실시간 GPS가 아닙니다.
- 녹색은 적재 운송, 황갈색 점선은 공차 이동, 차량 마커는 후보 거점입니다. 같은 좌표의 후보들은 숫자로 묶어 표시합니다.
- OSRM은 일반 자동차 도로 참고 경로입니다. 화물차 통행 제한, 축중, 도로 높이 제한, 실시간 교통을 검증하지 않습니다.
- 화면 거리·시간 및 예상 도착은 **기존 모델 OD 데이터** 기준입니다. 온라인 지도 도형과 차이가 있을 수 있습니다.
- 도로 조회 실패 시 해당 구간을 거점 연결선으로 표시하고 명시적인 안내를 표시합니다. 배경 지도 실패도 별도로 알리며 추천·확정 기능은 계속 작동합니다.
- 공개 지도는 사용량·가용성 보장이 없으므로 지속적 회사 운영 시 적절한 지도 공급자 또는 자체 서버로 전환하세요. 배포 시 [OSM 타일 이용 정책](https://operations.osmfoundation.org/policies/tiles/)을 준수해야 합니다. 대량 다운로드·오프라인 타일 수집은 구현하지 않았습니다.

## 테스트

모델·API 통합 테스트는 사용자 배차 파일과 분리된 임시 저장소로 실행됩니다.

```powershell
.\.venv\Scripts\python.exe tests/run_tests.py
```

실제 브라우저 테스트는 Chrome 설치가 필요합니다. 모델 응답은 Mock 처리하지 않으며, 지도 장애 시나리오에서만 외부 지도 요청을 차단합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe tests/browser_check.py
```

테스트는 임시 로컬 서버와 배차 저장소를 사용하고 종료 시 정리합니다. 화면 캡처는 `docs/screenshots/`에 생성합니다.

## 운영 및 데이터 주의사항

- 로컬 시연용 서버는 `127.0.0.1:5000`에 열립니다. 외부 인터넷에 자동 공개되지 않습니다.
- 현재 위치·상태는 요청한 상차 예정 일시 기준의 이력 상태이며 실시간 관제 단말과 연결되어 있지 않습니다.
- 중량 BLOCK은 각 기준값 이상일 때 적용됩니다. WARN은 배차 가능하나 실제 적재·통행 가능 여부를 담당자가 확인해야 합니다.
- 배차는 `data/runtime/dispatch_state.json`에 저장됩니다. 이 파일을 삭제·수정하면 확정 내역에 영향을 줍니다.
- 테스트 실행기 외에 개별 테스트 함수를 직접 호출하지 마세요. 표준 실행기가 임시 저장소를 설정합니다.
- 현재 JSON 저장소는 로컬 단일 프로세스 시연용입니다. 다중 사용자 실제 운영에는 DB 트랜잭션 기반 배차 잠금, 인증·권한 및 감사 이력이 필요합니다.
- 경로와 파라미터는 `config.py`에서 관리합니다. `DISPATCH_DATA_DIR`, `DISPATCH_SOURCE_DIR`, `DISPATCH_RUNTIME_DIR`, `DISPATCH_STATE_FILE` 환경변수로 재지정할 수 있습니다.
